## 2. LLM routing — fully local

`core/llm_router.py`:

- `route_llm_call()` routes to local mesh-llm only. The `use_cloud=True` argument is a **no-op** (retained for call-site compat, explicitly documented as unused).
- `call_anthropic()` exists as a standalone function for tasks the local model can't handle (VLM inventory parsing). It is **not called from the main runtime loop**; only from targeted call sites.
- Cloud fallback path is dead code. If local fails, returns `(None, None)` → bot takes `'wait'` action.
- API keys read from `~/.config/anthropic/key`, `~/.config/google/key` but not exercised at runtime.

**Conclusion: zero cloud API calls in the normal runtime path. Phase 1 (Honcho deriver) has a clear local-only target.**

## 3. Memory systems

### 3a. data/memory.db (SQLite, 5.1 MB)
Tables: `episodes`, `facts`, `procedures`
- `episodes`: **50,374 rows** — read/written by `memory/episodic.py`
- `facts`: semantic facts — `memory/semantic.py`
- `procedures`: procedural memory — `memory/procedural.py`

### 3b. data/aurora.db (SQLite, 137 MB)
Tables: `chests`, `human_episodes`, `episodes`, `entities`, `facts`, `relationships`
- `human_episodes`: **756,295 rows** — imitation learning; written every poll tick in HUMAN mode (`core/human_assist.py`)
- `chests`: chest inventory cache — `memory/chest_memory.py`
- `entities`: **2 rows** — entity tracking (`memory/aurora_memory.py`)

### 3c. data/cognitive/ (JSON files, read each tick)
- `belief_state.json` — current world belief
- `episodic_memory.json` — session episode log
- `goal_stack.json` — live goal stack
- `hotbar.json` — hotbar slot cache
- `inner_monologue.json` — LLM-generated thought (feeds back into VLM prompt)
- `inventory.json` — current inventory

### 3d. Which memory is actually read at runtime?
- **GoalStack** (`memory/goals.py`) — reads `data/goals.json` and `data/memory/retired_goals.jsonl`. This is the live goal tracking system.
- **EpisodeMemory** (`core/episode_memory.py`) — separate from cognitive/episodic_memory.json; SQLite-backed.
- `data/cognitive/` JSON files are written every tick by their respective modules. `inner_monologue.json` is confirmed to feed back into the VLM prompt (the only cognitive file that does).
- `data/cognitive/belief_state.json`, `goal_stack.json`, `inventory.json` etc. are written but **not confirmed** to be read back by anything except tests (consistent with comments in `core/cognitive.py` header: "none of the three were ever read back by anything").

**Key finding**: The cognitive JSON files are mostly write-only sinks. Real goal tracking: `memory/goals.GoalStack`. Real episode memory: `core/episode_memory.EpisodeMemory` (SQLite). Real semantic/procedural: `memory/semantic.py` + `memory/procedural.py` (memory.db).

## 4. Skill system

**Current `Skill` class** (`skills/skill_system.py`, ~32 KB):

```python
class Skill:
    name: str
    trigger_objects: list[str]      # YOLO label names that trigger this skill
    steps: list[SkillStep]          # timed action sequence
    avg_reward: float
    uses: int
    created: float
    last_used: float | None
    preconditions: dict             # {"has_item": [...], "yolo_visible": [...], "max_y_level": int}
    postconditions: dict            # {"inventory_gained": [...], "min_count": int}
    success_count: int
    failed_count: int
    blacklisted: bool
    universal: bool                 # env-agnostic skills (navigate_menu, etc.)
```

**No formal registry.** Skills are stored as JSON files in `data/skills/` (currently **48 files**).

**SkillSystem** class has:
- `find_best(current_objects)` → `(Skill, float) | (None, 0.0)`
- `find_candidates(current_objects)` → `list[(Skill, float)]`
- `_mine_recent()` → auto-mines skills from episode replay
- `evolve_skills()` → periodic pruning/blacklisting pass
- No `register()` method. No `find_applicable(belief_state)` (belief-state-aware lookup).

**Phase 2 target**: add `Skill` dataclass wrapper in `skills/skill_base.py`, add `registry.py` with `register()` + `find_applicable(belief_state)` + `describe_all()`, wrap existing behaviors (chop_tree, dig_up, eat, etc.) as registered skills with belief-state preconditions.
